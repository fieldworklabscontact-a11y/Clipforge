# Media pipeline

Imported video is decoded for metadata by an HTML video element. Formats and codecs depend on the browser; a file is rejected when the browser cannot obtain a finite duration and video dimensions. The original selected file is copied to IndexedDB under the current local user ID and asset ID. It is not uploaded and the original is not changed. Browser quota, clearing site data, browser eviction, using another device/origin, or a different browser can make media unavailable. Keep source originals and use the relink control when needed. This is local browser storage, not encrypted per-account storage; users sharing a browser profile should not treat it as confidential. Project metadata is persisted separately on the app server.

Preview uses one HTML video element and the active clip's source in/out mapping, plus an overlaid manual caption. While a clip is active, timeline progress follows media playback rather than wall-clock time; playback waits for seeking and buffering. Gaps use a wall-clock playhead. Missing media stops playback rather than pretending to play. Clips are non-overlapping. No thumbnails, waveforms, proxy files, multi-source compositing, independent audio mixing, decoding worker, or render pipeline are implemented. There is no rendered export. Stream-to-ZIP and the render queue package the originals instead: `project.json`, `captions.srt`, the source files this browser still holds and `manifest.json`, written as an uncompressed streaming ZIP with CRC32 and byte-accurate progress. Missing sources are listed as omitted rather than silently skipped, and a job fails when nothing can be packaged. Completed archives are stored in IndexedDB so they can be downloaded later; clearing site data removes them. No performance or preview/export equivalence claim is made.
