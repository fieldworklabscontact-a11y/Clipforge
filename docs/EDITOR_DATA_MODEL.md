# Editor data model

The existing `/api/projects` table stores `{id, name, data, updated}` scoped to the authenticated user. New editor documents use `data.schema = 1`. Documents with no schema are opened in the previous Studio; documents with an unknown schema or invalid structure are rejected instead of overwritten.

The schema holds settings `{width, height, fps, audioSampleRate}`, an array of video asset metadata, non-overlapping clips, and manual captions. Each clip contains `{id, assetId, start, sourceIn, duration}`: `start`, `sourceIn`, and `duration` are integer project-frame counts. A split creates two independent clips while preserving source offsets. A caption holds `{id, text, start, duration}` using project frames. Source metadata contains the browser-observed duration, dimensions, MIME type, file size and import date.

Frame rates are numeric, including fractional values such as 23.976. This is not rational-time representation; long-duration and mixed-frame-rate precision are not verified. Packages and jobs are not part of the project document. A package is derived on demand; job records live under `clipforge:queue:v1:<userId>:<projectId>` and completed archives in the IndexedDB `packages` store. Queued jobs hold a snapshot of the document, so later edits do not change a job that has already been queued. There are no video transforms, track objects, audio clips, effects or keyframes yet. Schema validation is performed on opening and before editor mutations. The server stores the provided object but does not independently validate the editor schema. There is no migration mechanism beyond preserving the legacy editor path and rejecting unsupported data. Schema-1 edits are copied to user- and project-scoped browser localStorage for recovery, validated before restoration, and compared with the saved project revision. Storage may be unavailable or cleared; this is not a substitute for a backup. Server writes from the new editor carry an expected update timestamp and reject concurrent changes with HTTP 409.
